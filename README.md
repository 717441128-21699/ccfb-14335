# 视觉小说剧本引擎（VN Script Engine）

给编剧用的**纯文本剧本格式** + 编译器 + 运行时引擎 + 可达性分析器 + 网页工具链。
编剧只写一种带选项、旗标、条件跳转的 `.vns` 文本，保存即编译，杜绝"程序手抄脚本、改剧情就漏"的问题。

## 解决的核心问题

1. **全结局可达性**：所有结局是否都能走到？走不到的缺哪几个旗标条件？
2. **死选项检测**：分支里有没有永远触发不了的选项 / 条件跳转？
3. **互斥旗标**：同一周目互斥的旗标（如只能加入一个社团）在分析时被精确建模，不会把凑不齐的组合误报成可达。
4. **网页试玩**：从任意场景开始、存档读档、历史回看、自动播放、跳过已读。

## 快速开始

```bash
npm install
npm run dev          # 打开 http://127.0.0.1:5173 ，四个标签页：编辑 / 分析 / 分支图 / 试玩

npm test             # 30 个单元测试
npm run analyze:cli scripts/sample.vns   # 命令行可达性报告（CI 可用，有问题退出码 2）
npm run gen:stress   # 查看压测剧本规模
npx tsx scripts/bench-stress.ts          # 30 万字 / 4000 旗标规模性能基准
npm run build        # 类型检查 + 生产构建
```

## 剧本语法（.vns）

```text
#title 剧本名
#entry 入口场景名
#mutex 组名: 旗标A, 旗标B, 旗标C     # 同周目内这些布尔旗标最多一个为 true

=== 场景名 ===
普通一行是旁白。
角色名：这是角色台词。
@set score = 10                       # 旗标赋值（布尔 / 数字 / 字符串）
@if score >= 20 and flag == true -> 目标场景   # 条件跳转
@goto 目标场景                         # 无条件跳转
@choice
  + 选项文本 -> 目标场景
  + 隐藏选项 -> 目标场景 if 条件 set 旗标=值, 另一旗标=true
@ending ending_id 结局显示名
```

### 条件表达式

- 比较运算：`== != >= <= > <`
- 逻辑：`and`、`or`、括号 `( )`，例：`a == true and (b >= 3 or c == "x")`
- 右值：`true` / `false` / 数字（含负数）/ `"字符串"` / 裸标识符（按字符串）
- 旗标名、场景名支持中文；未设置的旗标按右值类型取默认值（布尔→false、数字→0、字符串→""）
- 行尾注释用 ` //`（`//` 前需是行首或空白，`http://` 这类 URL 不会被误切）

### 编译器错误定位

每个错误都带**行号、列号、原始行文本**，网页编辑器左侧行号标红、右侧问题列表点击即跳转。
语义检查包括：场景重名、跳转到不存在的场景、场景未以控制指令结尾、空 `@choice`、
结局 id 重复、互斥组内旗标重复、孤儿场景、只读取未赋值的旗标（警告）等。

## 架构

```
.vns 文本
   │  compile()            src/core/compiler.ts
   ▼
CompiledScript（打平的指令序列 + 场景区间 + 互斥声明）
   ├── Engine               src/core/engine.ts      运行时：推进/选项/存档/自动/跳过
   ├── analyzeReachability  src/core/analyzer.ts    两层可达性分析
   └── buildSceneAdjacency                          分支图数据
```

### 可达性分析为什么又快又准

分析器分两层：

1. **抽象不动点（worklist + 三值域 true/false/unknown）**
   线性时间算出每个代码块的旗标取值过近似，立刻揪出"恒为 false"的死条件/死选项。
2. **具体状态 DFS + 互斥剪枝**
   枚举真实可行的旗标组合。互斥组内第二个被置 `true` 的旗标会让该路径当场失效，
   因此**不会把实际凑不齐的组合误报成可达（无假阳性）**。状态用稳定签名 + 包含关系去重，
   每个代码块设状态数上限，菱形分支不会指数爆炸。

不可达结局的诊断会区分：
- 控制流图层面就到不了（给出各入口恒假的原子条件，即"缺哪几个旗标"）；
- 抽象可达但具体路径被互斥规则剪掉（给出互斥组名和触发旗标）；
- 单边条件都可能成立、但组合互斥凑不齐。

### 性能基准（本机）

压测剧本由 `scripts/gen-stress.ts` 生成，约 **119 万字符、4000 旗标、2242 场景、3 万条指令、41 结局**：

| 阶段 | 耗时 |
| --- | --- |
| 编译 | ~50 ms |
| 全结局可达性分析 | ~7.7 秒（要求 < 10 秒）|

30 万字 / 2000 旗标规模下分析耗时约 2–3 秒，余量充足。

### 运行时与分析器语义一致

互斥规则不只用于分析：**引擎在每次旗标赋值时也强制执行互斥**——同组已有旗标为 `true` 时，
后续的 `true` 赋值会被拒绝并发出 `mutex-violation` 事件。`scripts/smoke-e2e.ts` 会枚举示例剧本的
全部选项路径，交叉校验"引擎实际走到的结局集合"与"分析器声明的可达结局集合"完全相同，
杜绝分析器说能走到、引擎却走不到（或反过来）的偏差。

## 网页工具

- **剧本编辑**：在线编辑、防抖自动编译、错误行高亮、点击问题跳转、导出编译产物 JSON。
- **可达性分析**：统计卡片 + 不可达结局诊断（缺失旗标、互斥冲突）+ 死分支列表。
- **分支图**：BFS 分层 SVG 图，入口/结局/不可达节点分色，点击任意节点直接从该场景试玩。
- **试玩**：任选起始场景、可预置旗标 JSON；存档/读档（localStorage 多槽位）、
  历史文本侧栏、当前旗标实时监视、自动播放、跳过已读（未读句自动停）。

## 示例剧本埋的测试点

`scripts/sample.vns` 是一个共通线 → 社团分支 → 好感度/数值判定 → 7 结局的结构，其中：

- `end_bad`：入口旗标 `dropped_out` 全剧本从未赋过值 → 报缺失条件；
- 天文同好会选项：要求 `affinity_lin >= 2` 但共通线凑不到 → 死选项；
- `end_impossible`：需要同时属于两个互斥社团 → 具体 DFS 在第二旗标赋值处剪枝；
- 其余 5 个结局全部可达。
